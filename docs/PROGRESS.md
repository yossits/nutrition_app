האפיון הקיים הוא **פונקציונלי** — מה המערכת עושה. אין אפיון **ויזואלי** — איך היא נראית ואיך מנווטים בה. מעוצב מסך אחד מתוך ~16.

- [ ] מלאי מסכים ומפת ניווט
- [ ] מערכת עיצוב — נגזרת מאב-הטיפוס הקיים
- [ ] ספריית רכיבים
- [ ] RTL לעומק — כיווניות, מספרים, גרפים, אנימציות
- [ ] נגישות — ניגודיות AA, הגדלת גופן מערכת, ניווט מקלדת
- [ ] מצבים — ריק, טעינה, שגיאה, נעול
- [ ] מיקרו-קופי — במיוחד בחסימות בריאותיות ובחומות תשלום
- [ ] **מסך בחירה בין חלופות.** נגזר מהחלטת 31.08 — המאגר מציע ואינו מכריע, ולכן "המשתמש בוחר" דורש מסך. ובצידו מכסת ההחלפות: **12 בקשות החלפת מזון בחודש**

**סדר מומלץ:** מערכת העיצוב קודם, אחריה האשף. האשף הוא המסך הראשון שמשתמש רואה וקובע אם הוא נשאר.

## איך לעדכן את הקובץ הזה

בסוף כל סשן עבודה:

1. סמן ✅ מה שהושלם. **רק אם הוא באמת עומד בהגדרת הסיום** — לא "כתבתי את הקוד" אלא "הרצתי אותו והוא עבר".
2. הזז את 📍 "אתה כאן" אם השלב התחלף.
3. עדכן את התאריך למעלה.
4. אם התקבלה החלטה — שורה חדשה ב-[`decisions.md`](decisions.md), ואז עדכון המודול ב-`spec/`.
5. אם נמדד משהו — שורה חדשה ב-[`measurements.md`](measurements.md).
