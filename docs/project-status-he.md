### באגים שהספייק תפס
1. **זמני ארוחות נשברו אחרי חצות** — קימה 07:00 ושינה 01:00 ייצרו זמן שלילי
2. **39% מהפרופילים ללא מאגר בר-בנייה** — טבעוני+כשר+אלרגיות הותיר אפס מקורות חלבון
3. **המודל התבקש לעשות חשבון** — 0% מעבר, חריגה טיפוסית +20%. תוקן בפותר-מנות → 100%
4. **`[drink/parve]` הועתק לתוך שם המזון** — כשל 1 מ-40
5. **הצמדה שנהרסה בתיקון** — "11 פרוסות לחם", "10 ג' אבוקדו"
6. **חצי ביצה, חצי זית** — יחידות שאין להן חצי
7. **קובץ שבור נשלח אחרי בדיקת תחביר בלבד** — ראה סעיף 13.5 באפיון

## 5. הצעד הבא

### א. מאגר משרד הבריאות (המסלול הארוך — להתחיל מיד)
זמין ב-**data.gov.il**, מאגר `nutrition-database`. 4,500+ פריטים, 74 רכיבי תזונה, ~1,400 מתכונים ישראליים, **ויחידות הגשה**. רישיון פתוח, מתאים למסחרי.

1. הורדת 4 הקבצים, ייבוא ל-Postgres, קישור לפי `CODE`, פענוח `Mida`
2. בדיקת שפיות: 30 פריטים מול תוויות אמיתיות
3. אצירה: סימון 300–400 פריטים כ-`menu_eligible`
4. תיוג ידני: כשרות · אלרגנים · `quality` · `unit`/`by_weight` · `whole_only`/`max_g`
5. טבלת ~50 מוצרים מסחריים ישראליים
6. ולידטור: אין פריט מובחר בלי כשרות ותיוג אלרגנים

**עומק לפי קטגוריה, לא מספר כולל.** שומן שורד 17% מהסינון, חלבון 20%, ירקות 67%. להעמיק במקורות שומן נטולי אלרגנים ובחלבון צמחי.

### ב. אפיון UI/UX — <mark>לא בוצע, פער פתוח</mark>

**זה השלב שהכי חסר.** האפיון הקיים הוא **פונקציונלי** — מה המערכת עושה. אין אפיון **ויזואלי** — איך היא נראית ואיך מנווטים בה.

**מה קיים היום:** מסך אחד בלבד — `מסך-תפריט-אבטיפוס.html`. זהו.

**מה חסר — מלאי מסכים משוער:**

| קבוצה | מסכים |
|---|---|
| כניסה | נחיתה · הרשמה · אימות SMS · התחברות |
| אשף | 7 מסכי שלב · מסך יעדים · מסך המתנה |
| ליבה | תפריט יומי ✅ · ארוחה מורחבת · בחירת חלופה · בקשת שינוי |
| מעקב | שקילה · גרף מגמה · מדידות היקפים |
| שלבים | סיום שלב · סיכום הישגים · תחילת שלב חדש |
| מסחר | מסך שדרוג · חומות תשלום · ניהול מנוי · ביטול |
| פרופיל | הגדרות · "מה למדנו עליך" · טקסט חופשי · עריכת העדפות |
| בטיחות | סינון בריאותי · מסך חסימה והפניה |
| מצבים | ריק · טעינה · שגיאה · אופליין |

**≈16 מסכים ועוד מצבים. אחד מהם מעוצב.**

**מה אפיון UI צריך להכיל:**
1. **מלאי מסכים ומפת ניווט** — מה מוביל לאן, איפה נמצא התפריט התחתון
2. **מערכת עיצוב** — פלטה, טיפוגרפיה עברית, מרווחים, רדיוסים, צללים
3. **ספריית רכיבים** — כרטיס, כפתור, שדה, צ'יפ, מונה, סרגל התקדמות, מודאל
4. **RTL לעומק** — כיווניות, מספרים, גרפים, אנימציות
5. **נגישות** — ניגודיות AA, הגדלת גופן מערכת, ניווט מקלדת
6. **מצבים** — ריק, טעינה, שגיאה, נעול
7. **מיקרו-קופי** — הניסוח בממשק, במיוחד בחסימות בריאותיות ובחומות תשלום

**סדר מומלץ:** מערכת העיצוב קודם (היא נגזרת מאב-הטיפוס הקיים), אחריה האשף — הוא המסך הראשון שמשתמש רואה וקובע אם הוא נשאר.

### ג. האשף (אחרי המאגר וה-UI)
מפרט **פונקציונלי** מלא בסעיף 7.0 באפיון. חסר לו אפיון ויזואלי. שווה אב-טיפוס עובד לפני קוד ייצור.

### ד. רגולציה — פתוח ולא נסגר
לפי חוק הסדרת העיסוק במקצועות הבריאות, כינוי הכולל את המילה "תזונה" — לרבות "יועץ תזונה" — מוגבל לבעלי רישיון ממשרד הבריאות. **דורש עו"ד לפני השקה מסחרית.** ההמלצה: לצרף דיאטן/ית קליני/ת כאחראי/ת מקצועי/ת — סוגר את החשיפה וגם משדרג את אמינות המוצר.
